# PERSONA

## 논의 사항

**페르소나 도출 범위**
- 사람: 김OO (나이, 성별, 직업) → 상황 고르기? (수업, 시험기간)
- 상황 or use case (운전, 운동, 데이트 등등)

**페르소나 도출 방안**
1. 있는 데이터로 최대한 재구성 + 임의로 지어내기
2. 지인들 데이터 공유 받아서 좀 더 다양한 페르소나 구성하기

**페르소나 웹 UI 플로우**
- 정의한 페르소나에 사용자가 원하는 혹은 맞는 페르소나가 없으면...??

**상황 복원 관련 추가 아이디어**
- 상황 복원 할 때 카카오톡 메신저, 이미지, 개인 로그 및 메모, 일기 등등 추가하기

## 구체적인 페르소나 정의

### 1. 김하린 — 바쁜 일상 속 자신의 상태를 놓치는 사회초년생

**Profile**
- 24세, 인턴 3개월 차
- 업무 중에는 긴장이나 피로를 알아차리지 못하고 퇴근 후에야 체감함
- 일기나 감정 기록은 번거로워 꾸준히 하지 못함

**Pain Points**
- 언제, 무엇 때문에 스트레스를 받았는지 기억하기 어려움
- 심박수나 수면 수치를 확인해도 실제 일상과 연결해 해석하기 어려움
- 하루가 지나면 편안함이나 성취감을 느낀 순간까지 함께 잊힘

> "그때는 괜찮다고 생각했는데, 퇴근하고 나서야 제가 많이 지쳐 있었다는 걸 알아요."

**Needs**
- 직접 기록하지 않아도 중요한 변화가 자동으로 포착되는 기능
- 생체신호를 일정, 위치, 활동 등 일상의 맥락과 함께 설명하는 기능
- 반복되는 스트레스와 회복 패턴을 알려주는 개인화된 인사이트

**대표 시나리오**
업무 회의 중 심박과 스트레스 지표가 크게 상승했지만 본인은 긴장을 인지하지 못한다. LIFELINE은
회의 일정과 생체신호를 연결해 해당 순간을 알려주고, 퇴근길 산책 후 빠르게 안정된 흐름까지 함께
보여준다.

### 2. 정유진 — 평범한 하루의 특별한 순간을 간직하고 싶은 대학생

**Profile**
- 22세, 대학교 3학년
- 수업, 과제, 동아리, 친구 약속 등 다양한 일정을 보냄
- 사진은 자주 찍지만 감정이나 상황을 별도로 기록하지 않음
- 건강관리보다 추억과 자기 이해에 더 관심이 많음

**Pain Points**
- 사진은 남아도 당시 왜 즐거웠는지는 시간이 지나면 잊어버림
- 평범한 하루에는 기억할 만한 일이 없었다고 느끼기 쉬움
- 기록을 위해 매번 앱을 켜고 입력하는 과정이 부담스러움

> "사진은 남아 있는데, 그 순간에 왜 그렇게 즐거웠는지는 금방 잊어버리는 것 같아요."

**Needs**
- 긍정적인 감정 변화가 있었던 순간을 자동으로 발견하는 기능
- 사진, 장소, 활동과 생체신호를 연결한 순간 카드
- 하루나 한 달의 의미 있는 순간을 모아주는 라이프 아카이브

**대표 시나리오**
친구들과 특별한 계획 없이 대화하던 시간에 안정적이고 활기찬 생체신호가 나타난다. LIFELINE은
당시 사진과 위치를 연결해 그 시간이 하루 중 가장 편안하고 즐거웠던 순간이었음을 알려준다.

### 3. 박민준 — 신체 데이터의 의미를 알고 싶은 대학생

**Profile**
- 23세, 대학교 4학년
- 운동과 건강관리에 관심이 많아 스마트워치 데이터를 자주 확인함
- 취업 준비와 학업으로 수면 및 생활 리듬이 불규칙함

**Pain Points**
- 심박수 상승이 운동, 긴장, 피로 중 무엇 때문인지 구분하기 어려움
- 데이터가 많이 쌓여도 생활을 바꿀 만한 인사이트는 얻지 못함
- 일반적인 건강 조언보다 개인의 상황에 맞는 설명이 필요함

> "심박수가 높았다는 건 알겠는데, 그게 운동 때문인지 긴장 때문인지는 모르겠어요."

**Needs**
- 개인의 평소 패턴과 비교한 변화 분석
- 활동, 수면, 일정 등을 함께 고려한 원인 해석
- 데이터에서 실제 행동으로 이어질 수 있는 구체적인 제안

**대표 시나리오**
움직임은 적었지만 발표 직전 심박 변동이 크게 나타난다. LIFELINE은 발표 일정과 전날 수면 부족을
함께 분석해 긴장과 피로가 영향을 미쳤을 가능성을 알려주고, 유사한 일정 전 수면과 휴식을 제안한다.

## 진행 상황

지인들의 실제 건강 데이터(`rawdata/`)를 받아서, 그 데이터가 실제로 보여주는 요일/시간대
패턴·각성 성격·만성 저조 빈도를 근거로 그럴듯한 페르소나 서사를 붙이는 작업 중이다.

| 페르소나 | 실제 데이터 소유자 | 이상치 이벤트 | 상태 |
|---|---|---|---|
| [student](student/README.md) | 김하은 | 76개 | 완료 |
| [office](office/README.md) | 김아연 | 46개 | 완료 |

### 방법

1. `scripts/parse_export.py`로 HealthKit 전체 내보내기(`export.xml`)를 바이탈/활동 CSV로 분리
2. `feelback_residual.py`로 이상치(감정성 각성 후보) 탐지 → `feelback_residual_episodes.csv`
3. 탐지된 이벤트의 요일/시간대/각성 성격 분포를 보고, 그 패턴과 가장 그럴듯하게 맞는
   페르소나 서사를 붙인다 (각 페르소나 폴더의 README.md 참고 — "대표 시나리오"에 쓸 수 있는
   구체적 이벤트 후보도 뽑아뒀다)
4. 실제 사진/채팅/영상은 `scripts/match_events.py`로 이벤트 시각과 매칭해 "사진·위치 기반
   장면 복원"에 사용 (위 필요한 기능 참고)

### 각 페르소나 폴더의 파일 구조

`student/`, `office/` 등 각 폴더 안엔 파일 4개가 있다 — **원본 데이터 2개**(측정값 그대로)와
**모델 결과 2개**(탐지 결과)로 나뉜다.

#### 원본 데이터 (`scripts/parse_export.py`가 애플 내보내기에서 뽑아낸 것)

**`export_vitals.csv`** — 순간 측정값. 심박수처럼 "그 순간 한 번" 잰 값들, 한 줄 = 측정 1건.

| 컬럼 | 의미 | 예시 |
|---|---|---|
| `display_name` | 무슨 지표인지 | `HRV SDNN`, `Heart rate`, `Respiratory rate` 등 |
| `timestamp` | 측정 시각 | 2026-07-16 08:27:59+09:00 |
| `value` | 측정값 | 13.8137 (ms) |
| `unit` | 단위 | ms, count/min 등 |
| `motion_context` | 그 순간 움직이고 있었는지 (심박수에만 있음, Apple이 자체 판단) | |
| `source_name` | 어느 기기가 쟀는지 | 김아연의 Apple Watch |

**`export_activity.csv`** — 구간 측정값. 걸음수처럼 "몇 분~몇 시간 동안 누적된" 값들, 한 줄 = 그 구간 하나.

| 컬럼 | 의미 | 예시 |
|---|---|---|
| `metric` | 무슨 활동 지표인지 | `active_energy`, `steps`, `flights` 등 |
| `start`/`end` | 그 구간의 시작~끝 | 2022-11-19 12:58:20 ~ 12:58:31 |
| `value` | 그 구간 동안 누적된 값 | 0.06 (kcal) |
| `source_name` | 기록한 앱/기기 | 서드파티 운동 앱 닉네임이 찍히기도 함 |

#### 모델 결과 (`feelback_residual.py`가 위 두 파일을 분석해서 만든 것)

**`feelback_residual_episodes.csv`** — 이상치 이벤트 (상황 복원의 핵심 입력). 한 줄 = 감지된 이상치 사건 1개.

| 컬럼 | 의미 |
|---|---|
| `start`/`end`, `duration_min` | 이벤트 시작~끝, 지속 시간(분) |
| `peak_hr` | 그 구간 중 최고 심박수 (실제값) |
| `expected_hr` | 모델이 예측한 "이 시간대·활동량이면 이 정도가 정상"인 값 |
| `excess_bpm` | `peak_hr − expected_hr` — 정상 대비 얼마나 초과했는지 (클수록 수상함) |
| `steps_5m` | 직전 5분 걸음수 — 운동 때문인지 확인용 |
| `hrv_ms` | 근처 HRV 값 (낮으면 스트레스 증거) |
| `hrr_slope` | 심박이 얼마나 빨리 진정되는지 (느리면 "지속성" 긴장) |
| `arousal` | 지속성(느리게 진정)/위상성(빠르게 진정)/빈칸(판단 불가) |
| `peak_z`, `score` | 이상함의 정도(z-score)와 최종 순위 점수 — 높을수록 확실한 이상치 |
| `evidence` | 위 숫자들을 사람이 읽을 문장으로 자동 요약한 것 |

예시: 기대치 85인데 실제 144까지 튀어서 초과 +59bpm, 걸음 0(운동 아님), 회복이 느려서
지속성 긴장으로 판정 — score가 높을수록 상위 후보.

**`feelback_daily_condition.csv`** — 하루 단위 컨디션. 한 줄 = 하루. 이벤트 탐지와는 별개로
"그날 하루 전체가 컨디션 저조였는지"를 본다.

| 컬럼 | 의미 |
|---|---|
| `hrv_day_med` | 그날 HRV 중앙값 |
| `hrv_ratio` | 그날 HRV가 평소(개인 중앙값) 대비 몇 %인지 (1.0 = 평소와 같음) |
| `resting_hr`, `rhr_delta` | 그날 안정시심박, 평소 대비 차이 |
| `low_condition` | 저조일로 판정됐는지(True/False) |
| `evidence` | 저조로 판정된 이유 (저조 아니면 빈칸) |

**정리**: vitals/activity는 "재료", episodes/daily_condition은 그 재료로 모델이 뽑아낸 "결과".
상황 복원에 실제로 쓸 건 `feelback_residual_episodes.csv`.
